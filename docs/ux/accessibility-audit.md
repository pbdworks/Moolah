## Audit aksesibilitas wireframe

**Scope:** `docs/ux/wireframes/` pada commit `b21b6f5`  
**Target:** WCAG 2.1 AA (audit statis; belum merupakan deklarasi konformansi)  
**Metode:** inspeksi HTML/CSS dan perhitungan kontras. Tidak ada pengujian browser, keyboard nyata, screen reader, zoom, atau axe pada sesi ini.

### Catatan heading dan semantik

Setiap file memiliki satu `<h1>` pada intro dan setiap `article.screen` memakai `<h2>`, sehingga urutan heading tidak melompat pada markup saat ini. `.balance` tidak menggantikan `<h2>` pada layar yang diperiksa; ia berada setelah heading (misalnya `02-kantong.html` dan detail `05-sisa-kantong.html`). Risiko yang tersisa adalah banyak screen disatukan dalam satu `<main>` dan tiap screen belum menjadi region yang diberi nama. Bila wireframe dipakai sebagai satu halaman interaktif, pertimbangkan `<section aria-labelledby="…">` per screen dan id heading unik.

### Prioritas perbaikan

1. **High — fokus visible (semua layar):** tambahkan `:focus-visible` yang kontras dan uji seluruh alur dengan keyboard.
2. **High — OCR state:** ubah kontrol kamera/retry menjadi button, beri live status untuk proses dan alert untuk gagal, serta hubungkan pesan “Perlu diperiksa” ke field.
3. **Medium — semantik aksi:** bedakan `<a>` untuk navigasi dan `<button>` untuk aksi/mutasi state; hapus bottom nav duplikat di `01`, `02`, `03`, dan `05`.
4. **Medium — skala teks/reflow:** naikkan teks penting ke ≥16px dan uji zoom 200%/reflow; pastikan nav serta target 44px tetap dapat digunakan.
5. **Medium — saldo/status:** jadikan saldo Beranda sebagai nilai utama yang berlabel dan pertahankan indikator tekstual “Hampir habis”/“minus” selain warna.

**Kesimpulan:** audit statis menemukan hambatan High yang memblokir keyboard visibility dan umpan balik OCR. Kontras dasar dan ukuran target nominal tampak memenuhi syarat, tetapi belum dapat dinyatakan lulus tanpa pengujian browser, zoom, screen reader, dan keyboard aktual.
